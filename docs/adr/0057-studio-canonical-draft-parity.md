# ADR-0057: Studio manual/JSON parity over canonical Content drafts

- Status: Accepted
- Date: 2026-10-06

## Decision

Studio is a Web authoring surface over Content-owned canonical CourseVersion state, not another persisted editor model. A working document exists only in component memory. Every manifest v1 field has a manual control: Course metadata, ordered Skills, all three quiz shapes and protected definitions, ordered Lessons, duration/summary, ordered YouTube/Markdown/Activity blocks including optional title, kind and required flag. JSON file/textarea and manual editing exchange that same document. Changing mode cannot silently discard invalid JSON. Slugs/keys bind stable identities; references update with manual key/slug edits and incomplete/deleted references fail full validation rather than being silently removed.

Both modes use ADR-0053 read-only manifest validation and revision-fenced atomic apply. The protected Studio snapshot returns the canonical exported manifest and exact draft identity/revision in one read-only repeatable-read transaction. The client compares a fresh plan with its loaded base; a fresh validation cannot authorize overwriting concurrent edits from a stale tab. Changed inputs invalidate the plan. Conflict or ambiguous mutation failure preserves the working copy and requires an explicit canonical reload. Saved JSON export is reconstructed by the existing draft export; downloading an unsaved working copy is labelled separately. No automatic save, upload persistence, local-storage draft, hidden membership or learner action is introduced.

Content owns protected Studio course discovery and reads. Lists filter current active-Membership assignments using the existing Authorization policy for both course.manage and activity.manage **before** bounded keyset pagination. Organization-level authority covers all organization courses; course-scoped assignments cover only the exact course. Import/next-draft additionally retain the existing organization skill.manage requirement; a course-scoped instructor can read protected Content and publish when authorized but cannot gain organization-wide Skill creation via Studio. Flags are presentation; existing server command authority remains decisive.

Organizations owns authenticated membership discovery. Migration 000043 adds one fixed-search-path, read-only, principal-bound locator function with at most 101 rows, requiring active Identity, Membership and Organization. It returns only own Organization id/slug/name and accepts only a cursor, never actor input. It grants no role or authoring authority and does not widen ordinary tenant RLS. The Web selects an Organization locator, then tenant-scoped Content authorization decides every operation. An explicit guarded create action delegates to the existing Organization creation/owner bootstrap and transactional outbox. Studio introduces no new role, capability, canonical table or event.

Author-only preview renders the validated working document with the same safe Markdown policy and renderer-owned YouTube host. It displays question/options/instructions but no protected validation fields and has no learner check command. Protected answers may enter only authorized Studio browser memory/forms/JSON downloads; they never enter anonymous HTML, public/learner projections, preview markup, outbox payloads or browser storage. Next.js receives only route locators; direct credentialed API reads require the existing HttpOnly session. Every new mutation uses exact-Origin guards. Author responses use no-store. Login reuses the existing auth flow and extends its strict local return allowlist only to /studio and validated UUID organization/course (or new) routes.

Studio publication requires exact draftVersionId and expectedRevision. Content checks the revision under its existing CourseVersion lock before complete manifest validation, immutable publication and the existing course_version.published event. A concurrent graph write either commits first and invalidates the preview or loses to publication and fails the existing draft fence. Legacy publication callers remain compatible without the optional revision argument. The UI permits publication only after previewing a saved, unchanged document. Publication does not create/change an Offering or public visibility.

The explicit next-draft action reads the latest authorized immutable manifest and passes it to the same importer with no expected draft and the latest published version-number fence. Competing creation/publication conflicts; stable identities and published history remain preserved. Incompatible legacy graphs fail closed instead of losing unsupported authoring data.

## Verification and frontier

Real-session PostgreSQL HTTP tests cover protected discovery/read authority, role-less and course-scoped access, strict caller/Origin boundaries, read-only preview, full field round-trip, revision fences, save/publication concurrency, outbox rollback and immutable next-draft history. Production Chrome verifies actual canonical Organization/Content APIs through Studio manual creation, JSON file upload, manual editing of imported shapes, protected preview, export, stale-tab conflict, publication and next draft. Existing non-canonical Commerce/learner UX seams remain separate. Full canonical learner browser flow and deployed HTTPS smoke remain Slice F. Production learner-code execution remains disabled.
