# Техническое задание: Nexus как игра — персонажи, сюжет, прокачка, оплата, испытатели

Версия 2, 2026-11-05. Заменяет версию 1 этого файла и `pricing-proposal.md`.

Задача владельца:
- учёба строится не как список курсов, а как прокачка персонажей ПК, Браузер, HTML, CSS и следующих;
- есть карта навыков, сюжет и игровая манера;
- продумано, за что платить;
- люди могут записаться в испытатели: временный бесплатный доступ в обмен на обязательную норму и отчёты о недочётах и предложения.

Документ рассчитан на автономную работу агента. Порядок источников истины — по `AGENTS.md`. Принятые ADR и код важнее этого документа.

---

## 1. Идея в одном абзаце

Ученик — новичок в городе **Нексус**, построенном из кода. Город разваливается: страницы рассыпаются, кнопки не нажимаются, данные теряются. Это работа **Бага**, вредного скрипта.

У каждого района есть хранитель — **персонаж-технология**: ПК, Браузер, HTML, CSS, JavaScript, SQL, позже Git, Терминал и другие. Хранители ослабли. Ученик прокачивает их, осваивая навыки. Каждый освоенный навык — способность персонажа, каждая ветка — восстановленная улица. Финальный проект ветки — **бой с Багом**, домашнее задание с проверкой.

Город на карте оживает вместе с прогрессом. Прогресс честный: его даёт только проверенное освоение навыков, а не клики.

**Правило о сюжете меняется по решению владельца от 2026-11-05.**
- Раньше в уроках сюжета не было.
- Теперь сюжет живёт в **игровой оболочке**: карта, сцены между ветками, бои, реплики персонажей.
- Объяснения в уроках остаются нейтральными и полными, без внешних ссылок. Сюжет не мешает учиться и не подменяет объяснение.
- Тесты запрета слов `Зерно`/`Марта`/`кофейня` остаются: старая история не возвращается.

## 3. Персонажи

Каждый персонаж — технология с характером. Его способности — навыки, ветки — улицы района, финал — бой с Багом.

| Персонаж | Класс | Характер | Район города | Даёт ученику |
|---|---|---|---|---|
| **ПК** (Кремень) | Фундамент | Старый надёжный системный блок, ворчит, но всё помнит | Машинный зал | Устройство компьютера, файлы, память, процессы, диагностика |
| **Браузер** (Бро) | Проводник | Быстрый, любопытный, всё время что-то открывает | Ворота в Сеть | Адреса, запросы, вкладки, DevTools, безопасность в вебе |
| **HTML** | Зодчий | Педантичный строитель: «сначала каркас» | Квартал Каркасов | Разметка, структура, формы, доступность |
| **CSS** | Художник | Стильный, спорит о каждом пикселе | Галерея | Оформление, вёрстка, адаптивность, анимации |
| **JavaScript** | Механик | Изобретатель, всё оживляет, иногда взрывает | Мастерские | Логика, события, асинхронность, весь стандарт |
| **SQL** (Слон) | Хранитель | Спокойный, огромная память, любит порядок | Архив | Запросы, данные, таблицы, аналитика |
| **Git** (позже) | Хронист | Помнит каждую версию, умеет откатывать время | Часовая башня | Версии, ветки, слияния, совместная работа |
| **Терминал** (позже) | Заклинатель | Немногословен, команды как заклинания | Подземка | Командная строка, файлы, скрипты |
| **Сеть/HTTP** (позже) | Почтальон | Носит пакеты, знает все маршруты | Почтамт | HTTP, DNS, API, кэш |

Сквозные герои:
- **Ника** — наставница-рассказчица: ведёт по карте и объясняет, что дальше.
- **Лев** — житель, который слушает сайты скринридером. Он напоминает про доступность и приходит на бои HTML и CSS.
- **Баг** — антагонист. Ломает районы; его «рои» — задания на поиск ошибок.

Правила:
- В персонаже нет ничего платного «за силу»: уровень — это только освоенные навыки.
- Облик персонажа, рамки и титулы растут с уровнем. Это награда, а не покупка.

## 4. Сюжет

**Структура:** пролог, затем акт на каждого персонажа, затем финал сезона.

- **Пролог (ПК, Браузер).**
  - Ученик просыпается в Машинном зале. Кремень (ПК) учит основам.
  - Бро (Браузер) открывает Ворота в Сеть и показывает, что город рушится.
  - Ника объясняет правила.
- **Акт HTML.** Каркасы домов разваливаются. Зодчий восстанавливает квартал улица за улицей, это ветки. Бой: Баг ломает страницу, ученик собирает её заново (домашнее задание).
- **Акт CSS.** Галерея обесцвечена, всё съехало. Художник возвращает цвет и порядок.
- **Акт JavaScript.** Мастерские остановились. Механик оживляет кнопки, формы и часы.
- **Акт SQL.** Архив перепутан. Слон восстанавливает данные.
- **Финал сезона.** Баг уходит в Часовую башню (Git), это крючок на следующий сезон.

**Как сюжет подаётся.** Без длинных текстов:
- **сцена** — 3–6 реплик в стиле мессенджера, существующий блок `story`, при входе в ветку и после боя;
- **реплика персонажа** на карте над следующим навыком;
- **район на карте** меняется по проценту освоения: серый → в лесах → живой.
- Сцены можно пропустить. Учёба без сюжета работает полностью.

**Хранение.** Сцены — часть карты (`skill-map@2`): у ветки есть `intro`, `outro` и `boss`. Тексты пишет агент, правит владелец.

## 5. Прокачка: механики

Всё вычисляется из Evidence, Mastery и истории событий. Нового изменяемого «счёта очков» нет: его нельзя накрутить, и он не расходится с учёбой.

| Механика | Правило | Откуда данные |
|---|---|---|
| **Опыт персонажа** | Σ mastery × 100 по его навыкам | Mastery |
| **Уровень персонажа** | 0–10 по доле освоенных навыков (mastery ≥ 0.8) | Mastery |
| **Уровень игрока** | Сумма уровней всех персонажей; титулы: Новичок → Подмастерье → Инженер → Архитектор | Вычисляется |
| **Ветка открыта** | Требуемые ветки освоены хотя бы на 50% (подсказка, не запрет) | Карта + Mastery |
| **Бой с Багом** | Домашнее задание в конце ветки. Пройдено — улица «восстановлена», значок | Evidence задания |
| **Ржавчина** | Освоенный навык, у которого подошёл срок повторения, тускнеет. Квиз по нему снимает ржавчину. Уровень не падает, это напоминание | ADR-0038 |
| **Задания дня** | 3 в день: повторить заржавевший навык, освоить следующий, решить практику. Новые каждый день | Карта + Mastery + расписание |
| **Серия** | Дни подряд с хотя бы одним засчитанным заданием; 1 «заморозка» в неделю | История событий |
| **Достижения** | Первый навык; уровень 5 и 10 персонажа; все бои акта; серия 7/30/100; «Охотник на Багов» за принятые отчёты испытателя | Вычисляются |
| **Рои Бага** | Задания «найди ошибку» в уже освоенных ветках: в коде спрятан баг, надо найти и исправить | Существующие challenge-блоки с ошибкой |

Сознательно **не делаем**:
- рейтинги между учениками на старте (давление и списывание);
- покупку опыта;
- лутбоксы;
- штрафы, отнимающие прогресс.

## 6. Монетизация: за что платить

### Принципы

1. Платят за **доступ к районам и проверку работ**, никогда за скорость или силу.
2. Пролог и первый акт бесплатны полностью: ученик должен влюбиться до оплаты.
3. Купленное и освоенное не отнимается. Прогресс сохраняется и после окончания доступа.

### Уровни доступа

| | Бесплатно | Сезонный пропуск | Персонаж навсегда |
|---|---|---|---|
| ПК, Браузер, HTML целиком | ✓ | ✓ | ✓ |
| Первые 2 ветки CSS, JS, SQL | ✓ | ✓ | ✓ |
| Все ветки всех персонажей | — | ✓ | только купленный |
| Бои с Багом (домашние задания с проверкой) | в бесплатных ветках | ✓ | купленного |
| Задания дня, серии, достижения, карта | ✓ | ✓ | ✓ |
| Новые персонажи сезона | — | ✓ сразу | отдельно |
| Сертификат персонажа на уровне 10 | — | ✓ | купленного |

**Сезонный пропуск** — разовая оплата за доступ ко всему на 3 месяца. Это Entitlement с `expires_at`.
- Почему не подписка: подписок в коде нет. Разовая оплата уже построена. Сезон проще юридически: нет автосписаний, понятно, за что заплачено.
- Продление — новая покупка.
- Варианты: 1 месяц, 3 месяца, 12 месяцев со скидкой.

**Персонаж навсегда** — для тех, кто не хочет сезон: разовая покупка одного персонажа. Entitlement без срока.

**Стартовые цены** — гипотеза для проверки владельцем по рынку. Агент рынок не проверял.

| Что | Гипотеза |
|---|---|
| Пропуск, 1 месяц | 690–990 ₽ |
| Пропуск, 3 месяца | 1 790–2 490 ₽ |
| Пропуск, 12 месяцев | 4 990–6 990 ₽ |
| Персонаж навсегда | 1 490–2 490 ₽ |

### Блокеры до приёма денег

Это обязательно, а не пожелания.

1. **Провайдер для России.** Paddle, по имеющимся сведениям, не работает с картами российских банков: владельцу нужно проверить. Альтернатива — ЮKassa или CloudPayments: отдельный ADR по образцу ADR-0048, чеки по 54-ФЗ провайдер отправляет сам.
2. **Оферта, политика конфиденциальности, согласие на обработку ПД.** Черновик — #174.
3. **152-ФЗ.** Персональные данные граждан РФ при сборе хранятся в России. Решение в #174.
4. **Возвраты** за неиспользованный срок и отзыв Entitlement. Сейчас не построены.

## 7. Программа испытателей («Отряд испытателей»)

**Цель:** живые люди проходят игру до запуска оплаты и приносят отчёты о недочётах и предложения. Взамен они получают полный доступ бесплатно на время.

### Поток

1. **Заявка.** Страница `/testers` → форма:
   - уровень подготовки;
   - сколько часов в неделю готов уделять;
   - устройство и браузер;
   - как связаться (email аккаунта);
   - согласие с правилами испытателя и с обработкой данных.
   Нужен вход в аккаунт.
2. **Отбор.**
   - Владелец видит заявки в Studio («Испытатели») и принимает или отклоняет.
   - Набор идёт волнами, у волны есть лимит мест (например, 30).
   - Можно включить автоприём, пока есть места.
3. **Доступ.**
   - Принятый получает Entitlement «Пропуск испытателя» на 4 недели: всё, что даёт сезонный пропуск.
   - Источник Entitlement — `tester_grant`, а не Purchase.
4. **Норма** на каждую неделю (настраивается на волну):
   - не меньше 3 активных дней (засчитанное задание в день);
   - не меньше 5 навыков с новым Evidence;
   - не меньше 2 отчётов (недочёт или предложение), хотя бы 1 из них не отклонён как пустой.
5. **Контроль.**
   - Норма вычисляется из истории событий и отчётов, без отдельного планировщика: статус считается при каждом входе.
   - Испытатель видит прогресс нормы на своей странице и в шапке.
   - Неделя без нормы — предупреждение. Две подряд — пропуск испытателя закрывается, остаётся бесплатный уровень, прогресс сохраняется.
   - Выполнил норму все 4 недели — продление на следующую волну и значок «Ветеран отряда».
6. **Отчёты.**
   - Кнопка «Сообщить» на каждой странице урока, карты и персонажа.
   - Поля: тип (ошибка / непонятно / предложение), текст, автоматически страница, урок, версия сайта и браузер. Скриншот — позже.
   - Ограничение частоты как у остальных записей (ADR-0070).
   - Владелец в Studio ведёт отчёты по статусам: новый → принят / дубль / отклонён → исправлен.
   - Испытатель видит статусы своих отчётов. Каждый принятый отчёт — «трофей» в коллекции Охотника на Багов: это связь с сюжетом.

### Модель (Delivery и новые модули)

- **`tester_programs` / `tester_waves`** — волна: даты, лимит мест, норма.
- **`tester_applications`** — заявка: статус `pending` → `accepted` / `rejected` / `withdrawn`.
- **`feedback_reports`** — отчёт, его статус и связь со страницей. Отчёты может присылать любой ученик; для испытателя они входят в норму.
- **Entitlement с источником `tester_grant`.** Commerce сейчас создаёт Entitlement только через Purchase. Нужен ADR: допустимые источники Entitlement (`purchase` | `tester_grant` | `operator_grant`), атомарность с событием outbox.

Все таблицы — с RLS по организации. Каждая смена статуса пишется вместе с событием outbox в одной транзакции.

## 8. Этапы

Каждый пункт — отдельная ветка и PR по `docs/engineering/development-workflow.md`.
- Порядок: локально `pnpm check` под общей блокировкой, интеграционные тесты и e2e для затронутого.
- Затем CI, squash-слияние и проверка продакшена (`/v1/health` release, страницы 200).
- Миграции продакшена применяет владелец. Код, которому нужна миграция, сливается только после того, как владелец её применил.

## 9. Правила автономной работы

- **Можно без вопросов:**
  - код, тесты, ADR, документация;
  - новые страницы и ссылки на них;
  - тексты сюжета;
  - сливать свои зелёные PR.
- **Нельзя без владельца:**
  - применять миграции продакшена;
  - сливать код, которому нужна неприменённая миграция;
  - включать оплату и цены;
  - публиковать курсы;
  - заменять главную и каталог;
  - удалять контент;
  - force push.
- Если продакшен после слияния отвечает не 200 или release не совпадает — сразу revert-PR, затем разбор.
