# Игровой дизайн Nexus: персонажи, сюжет, прокачка, оплата, испытатели

Версия 3, 2026-11-05. Описывает, **что** мы строим: модель персонажей и навыков, сюжет, механики, оплату и программу испытателей. **Как и в каком порядке** строим — в рабочем ТЗ `docs/roadmap/spec.md`. Решения, закреплённые в коде, — в ADR-0074–0079.

---

## 1. Идея в одном абзаце

Ученик — новичок в городе **Нексус**, построенном из кода. Город разваливается: страницы рассыпаются, кнопки не нажимаются, данные теряются. Это работа **Бага**, вредного скрипта.

У каждого района есть хранитель — **персонаж-технология**: ПК, Браузер, HTML, CSS, JavaScript, SQL, позже Git, Терминал и другие. Хранители ослабли. Ученик прокачивает их, осваивая навыки. Каждый освоенный навык — способность персонажа, каждая ветка — восстановленная улица. Финальный проект ветки — **бой с Багом**, домашнее задание с проверкой.

Город на карте оживает вместе с прогрессом. Прогресс честный: его даёт только проверенное освоение навыков, а не клики.

## 2. Что уже есть и на что опираемся

| Есть в коде | Как используем |

| Политика повторения по расписанию (ADR-0038) | «Ржавчина» навыков и ежедневное повторение |
| История событий ученика (ADR-0022) | Серии дней, достижения, норма испытателя — вычисляются |
| Entitlement с `expires_at` (миграция 000008), Product/Price, Paddle (ADR-0044–0052) | Подписка, доступ испытателей |
| Персонажи-помощники уроков: bro (браузер), nika (наставница), lev (слушает сайты скринридером), slon (база данных), bug (Вредный Скрипт) | Становятся героями сюжета (раздел 4) |

**Правило о сюжете меняется по решению владельца от 2026-11-05.**
- Раньше в уроках сюжета не было.
- Теперь сюжет живёт в **игровой оболочке**: карта, сцены между ветками, бои, реплики персонажей.
- Объяснения в уроках остаются нейтральными и полными, без внешних ссылок. Сюжет не мешает учиться и не подменяет объяснение.
- Тесты запрета слов `Зерно`/`Марта`/`кофейня` остаются: старая история не возвращается.

## 3. Персонажи: каждая технология — отдельный герой

Решение владельца от 2026-11-05. Персонаж — это не курс и не глава, а **отдельный герой со своим профилем**:
- навыки персонажа — это все возможности технологии, буквально;
- навык не даётся за просмотр, только за **изучение и подтверждение тестом**;
- навык со временем **забывается**, если его не повторять;
- персонажей много: не только то, что уже есть, но и React, Vue, Angular, Next.js и десятки других.

### 3.1 Профиль персонажа

| Поле | Что это |
|---|---|
| Имя и облик | Технология с характером (`docs/story/season-1.md`): Кремень (ПК), Бро (Браузер), Зодчий (HTML), Кисть (CSS), Искра (JavaScript), Слон (SQL) и новые |
| Класс | Роль в команде: Фундамент, Проводник, Строитель, Художник, Механик, Хранитель, Архитектор, Связной, Страж… |
| Версия технологии | Какую версию покрывает персонаж: HTML Living Standard, ECMAScript 2025, React 19, Next.js 16… Выход новой версии — «обновление персонажа»: новые навыки, устаревшие помечаются |
| Навыки | Все возможности технологии, сгруппированные в ветки. Каждый навык — одна возможность или тесно связанная группа: «хук `useEffect`», «`position: sticky`», «оконные функции» |
| Уровень | 0–100: доля **активных** навыков (подтверждённых и не забытых) × 100. Уровень может снижаться, если навыки забываются |
| Опыт | Сумма за все подтверждения, включая повторные. Опыт не сгорает: это стаж персонажа, он виден в профиле |
| Ранг | По уровню: Новичок (0–19) → Ученик (20–39) → Практик (40–59) → Мастер (60–79) → Эксперт (80–94) → Легенда (95–100) |
| Союзники и эволюции | Требования между персонажами. «Эволюция» — следующий персонаж той же линии: JavaScript → TypeScript, React → Next.js, Vue → Nuxt. Открывается, когда базовый персонаж на нужном ранге |
| Способности | Ключевые навыки-вехи, которые показываются значками на портрете. Например у React: «Компоненты», «Состояние», «Эффекты», «Контекст», «Серверные компоненты» |

### 3.2 Ростер: мир технологий

Полные деревья навыков всех 32 персонажей — с источниками полноты, ветками, ключами навыков, опорами, боями, способностями и правилами прокачки — лежат в `docs/product/skill-trees/` (README — методика).

Персонажи живут в районах-категориях. Требования — это не запрет учить, а условие **подтверждения**: тест навыка открыт, когда подтверждены навыки, на которых он стоит (раздел 5).

| Район | Персонажи | Стоит на |
|---|---|---|
| **Машинный зал** (фундамент) | ПК, Операционная система, Терминал (shell), Сеть/HTTP, Git | — |
| **Ворота** (веб-платформа) | Браузер, HTML, CSS, JavaScript, TypeScript, Web API (DOM, Fetch, Storage, Workers), Доступность, Безопасность веба | Фундамент |
| **Галерея** (стили) | Sass, Tailwind CSS, CSS Modules, Дизайн-системы | CSS |
| **Мастерские фреймворков** | React, Vue, Angular, Svelte, Solid | JavaScript (+TypeScript для Angular) |
| **Башни мета-фреймворков** | Next.js, Nuxt, SvelteKit, Remix / React Router, Astro, Angular SSR | Свой фреймворк |
| **Состояние и данные клиента** | Redux, Zustand, TanStack Query, Pinia, RxJS | Свой фреймворк |
| **Сервер** | Node.js, Express, NestJS, Deno/Bun, Python, FastAPI, Django, Go, Java + Spring, PHP + Laravel | JavaScript или свой язык |
| **Архив** (данные) | SQL/PostgreSQL, MongoDB, Redis, Prisma, Drizzle, GraphQL, REST-дизайн | SQL или сервер |
| **Испытательный полигон** (качество) | Vitest/Jest, Playwright, Testing Library, ESLint/Prettier | Язык или фреймворк |
| **Порт** (инфраструктура) | Docker, Kubernetes, Nginx, CI/CD (GitHub Actions), Linux-администрирование, облака | Терминал, Сеть |
| **Мобильный причал** | React Native, Flutter (Dart), Swift, Kotlin | Язык или фреймворк |

**Очередь вывода персонажей** (решение владельца, см. `docs/roadmap/spec.md`):
1. Сезон 1 — фундамент веба: ПК, Браузер, HTML, CSS, JavaScript, SQL. Контент есть, кроме полного ПК и Браузера.
2. Сезон 2 — Git, Терминал, Сеть/HTTP, TypeScript.
3. Сезон 3 — React, Next.js, Vue, Nuxt, Angular.
4. Дальше — по спросу из заявок и опросов учеников.

### 3.3 Полное покрытие технологии

«Все возможности технологии можно изучить буквально» — это проверяемое требование, а не лозунг.

У каждого персонажа есть **индекс покрытия** `coverage-index.json`. Это список всех возможностей технологии из её официальной спецификации или справочника:
- HTML — все элементы и атрибуты стандарта;
- CSS — все свойства, селекторы и правила;
- JavaScript — оглавление ECMAScript (уже сделано: `docs/examples/js-course/spec-index.json`);
- React — все API из справочника: хуки, компоненты, `react-dom`, серверные API;
- Next.js — все функции, файлы-соглашения, конфигурация.

Тест контента проверяет, что каждая запись индекса покрыта хотя бы одним навыком и уроком. Пропуск — красный тест. Индекс обновляется с новой версией технологии.

**Источник индекса** — официальная документация: агент составляет список по оглавлению справочника. Сами уроки пишутся своими словами, без копирования текста документации и без ссылок «читай там» (правила контента).

## 4. Сюжет

**Структура:** пролог, затем акт на каждого персонажа, затем финал сезона.

- **Пролог (ПК, Браузер).**
  - Ученик просыпается в Машинном зале. Кремень (ПК) учит основам.
  - Бро (Браузер) открывает Ворота в Сеть и показывает, что город рушится.
  - Ника объясняет правила.
- **Акт HTML.** Каркасы домов разваливаются. Зодчий восстанавливает квартал улица за улицей, это ветки. Бой: Баг ломает страницу, ученик собирает её заново (домашнее задание).
- **Акт CSS.** Галерея обесцвечена, всё съехало. Художник возвращает цвет и порядок.
- **Акт JavaScript.** Мастерские остановились. Механик оживляет кнопки, формы и часы.
- **Акт SQL.** Архив перепутан. Слон восстанавливает данные.
- **Финал сезона.** Баг уходит в Часовую башню (Git), это крючок на следующий сезон.

**Как сюжет подаётся.** Без длинных текстов:
- **сцена** — 3–6 реплик в стиле мессенджера, существующий блок `story`, при входе в ветку и после боя;
- **реплика персонажа** на карте над следующим навыком;
- **район на карте** меняется по проценту освоения: серый → в лесах → живой.
- Сцены можно пропустить. Учёба без сюжета работает полностью.

**Хранение.** Сцены — часть карты (`skill-map@2`): у ветки есть `intro`, `outro` и `boss`. Тексты пишет агент, правит владелец.

**Полный режиссёрский сценарий** — `docs/story/season-1.md`: экспликация, мир, библия персонажей, сцены на каждую из 84 веток, финал сезона, реплики-реакции и правила для сценаристов. Имена хранителей там: Кремень (ПК), Бро (Браузер), Зодчий (HTML), Кисть (CSS), Искра (JavaScript), Слон (SQL).

## 5. Навык: изучить → подтвердить → удерживать

Центральная механика. Навык проходит один и тот же цикл у любого персонажа.

### 5.1 Цикл навыка

```
закрыт ──(подтверждены опоры)──▶ открыт ──(изучен урок)──▶ изучен
изучен ──(сдан тест навыка)──▶ подтверждён ──(срок вышел)──▶ тускнеет
тускнеет ──(повторный тест сдан)──▶ подтверждён, срок длиннее
тускнеет ──(льгота вышла)──▶ забыт ──(тест сдан)──▶ подтверждён, срок короче
```

| Состояние | Что значит | Что видно |
|---|---|---|
| **Закрыт** | Не подтверждены навыки-опоры (раздел 5.3) | Серый, замок, список того, что подтвердить сначала. Урок читать можно, тест — нет |
| **Открыт** | Опоры подтверждены | Цвет персонажа, «Изучить» |
| **Изучен** | Урок пройден: прочитан, практика решена | «Подтвердить» — кнопка теста |
| **Подтверждён** | Тест сдан, срок не вышел | Яркий, значок, дата следующего повторения. Считается в уровне |
| **Тускнеет** | Срок вышел, идёт льгота (7 дней) | Налёт ржавчины, «Повторить». Ещё считается в уровне |
| **Забыт** | Льгота вышла | Трещина, «Вспомнить». **Не считается в уровне**. Навыки, которые на нём стоят, снова закрыты для подтверждения |

### 5.2 Подтверждение: тест навыка

- **Тест навыка** — 5 случайных вопросов из **банка навыка**, в банке не меньше 12 вопросов разных типов:
  - один ответ;
  - несколько ответов;
  - короткий ответ;
  - «что выведет код»;
  - «найди ошибку»;
  - порядок шагов.
  Для навыков, где это нужно, вместо вопроса — практическое задание с серверной проверкой (раздел 5.5).
- Порог — 4 из 5. Ответы проверяет сервер, правильные ответы в браузер не уходят (как сейчас у квизов, ADR-0056).
- Не сдал — разбор ошибок с подсказками, повтор через 10 минут с другими вопросами. Штрафов нет.
- **Экстерн.** Опытный ученик может сразу сдать **тест ветки** — по вопросу на каждый навык. Сданный тест подтверждает все навыки ветки.
- **Бой с Багом** — финальное задание ветки (`docs/story/season-1.md`). Открыт, когда все навыки ветки подтверждены и не забыты. Победа даёт значок ветки и большой опыт.

### 5.3 Опоры: что нужно подтвердить раньше

- У навыка есть **опоры** — навыки, без которых его не понять. Опоры могут быть внутри персонажа и у других персонажей: `useEffect` (React) стоит на «замыканиях» и «промисах» (JavaScript).
- **Тест навыка открыт только при подтверждённых и не забытых опорах.** Это и есть «чтобы что-то пройти, нужно изучить и подтвердить».
- Учить, то есть читать урок, можно всегда: знание не запирается, запирается только подтверждение.
- Опоры задаются на уровне навыков. Ветки по умолчанию идут цепочкой, а между персонажами есть явные связи. Граф без циклов, это проверяется тестом.

### 5.4 Срок навыка (интервальное повторение)

Каждое успешное подтверждение в отдельный день продлевает срок:

| Подтверждение | Срок до повторения |
|---|---|
| 1-е | 3 дня |
| 2-е | 7 дней |
| 3-е | 21 день |
| 4-е | 2 месяца |
| 5-е | 6 месяцев |
| 6-е и дальше | 1 год |

Как работает срок:
- Повтор раньше срока не считается новой ступенью, но обновляет дату.
- После срока — 7 дней льготы (тускнеет), затем навык забыт.
- Вспомнить забытый навык — сдать тест. Ступень при этом откатывается на одну назад: память ослабла, значит, следующий срок короче.
- **Нагрузка повторения.** Задания дня сначала предлагают тускнеющие навыки. Если тускнеющих больше 15, Ника предлагает «день повторения» вместо новых навыков.
- Срок и состояние вычисляются из истории подтверждений: Evidence с исходом «пройдено» и её дат. Это производная политика по образцу ADR-0038, её не нужно хранить. Ступени и сроки — параметры политики с версией (`skill-freshness@1`).

### 5.5 Практические подтверждения

Для части навыков вопросов мало: «сверстай», «напиши компонент», «сделай запрос».
- **HTML, CSS** — файловые задания с серверной статической проверкой: уже работают (ADR-0073).
- **SQL** — запрос выполняется в учебной базе и сравнивается с эталоном. Нужна серверная песочница для SQL: отдельный ADR. В браузере есть PGlite, но браузеру нельзя доверять как источнику подтверждения.
- **JavaScript, TypeScript, React, Vue, Angular, Next.js и сервер** — код нужно исполнять. Для этого в репозитории есть грейдер (F7: шлюз, очередь, Go-раннер, песочница gVisor), но в продакшене он выключен. **Включение грейдера — обязательное условие практических подтверждений для персонажей-фреймворков.** Это отдельный этап с проверкой безопасности (`docs/roadmap/spec.md`, фаза 4). До него навыки фреймворков подтверждаются вопросами: код на чтение, «что выведет», «найди ошибку».

### 5.6 Остальные механики

| Механика | Правило |
|---|---|
| Уровень игрока | Сумма уровней всех персонажей; титул по сумме |
| Задания дня | 3 в день: повторить тускнеющий навык, подтвердить новый, решить практику или рой Бага |
| Серия | Дни подряд хотя бы с одним подтверждением; 1 «заморозка» в неделю |
| Достижения | Первое подтверждение; ранги персонажей; все бои акта; серии 7/30/100; «Ни одного забытого» за 90 дней; принятые отчёты испытателя |
| Рои Бага | «Найди и исправь» в подтверждённых ветках; засчитываются как повторение |

Не делаем:
- рейтинг между учениками на старте;
- покупку опыта или сроков;
- лутбоксы;
- уровни «за время на сайте».

### 5.7 Где живёт логика (архитектура)

| Что | Модуль | Как |
|---|---|---|
| Персонажи, ветки, навыки, опоры, версии технологий, индексы покрытия | Learning Content | Этап 1 — файл `skill-map` в Web (ADR-0074). Этап 2 — публикуемая неизменяемая версия карты в базе (миграция) |
| Банк вопросов навыка, тест навыка, тест ветки | Learning Content (защищённые ответы) + Learning Validation | Расширение квизов ADR-0056: набор из банка, серверная проверка, Evidence на навык |
| Подтверждения, срок, состояние навыка | Learning Progress | Производная политика `skill-freshness@1` поверх Evidence. Этап 1 — расчёт в Web по API подтверждений, этап 2 — на сервере |
| Запрет подтверждения без опор | Learning Progress / Validation | Сервер отказывает в тесте (409 `prerequisites_not_confirmed`), когда карта в базе (этап 2). До этого запрет только в интерфейсе |
| Доступ к персонажам по подписке | Commerce + Delivery | Entitlement (раздел 6) |

Нужные ADR:
- **ADR-0075** «Тест навыка, банк вопросов и подтверждение»;
- **ADR-0076** «Срок навыка `skill-freshness@1`»;
- **ADR-0077** «Опоры навыков и серверный запрет подтверждения»;
- **ADR-0078** «Карта персонажей как публикуемая версия Learning Content».

### 5.8 Фабрика контента

Персонажей будут десятки, у каждого 100–400 навыков. Без конвейера это не сделать. На каждого персонажа:

1. **Индекс покрытия** из оглавления официального справочника технологии нужной версии.
2. **Дерево навыков:** группировка индекса в навыки и ветки, опоры внутри персонажа и к другим персонажам.
3. **Урок на навык:** объяснение, примеры, живая практика в браузере. Правила контента прежние: полно, своими словами, без внешних ссылок.
4. **Банк вопросов на навык:** не меньше 12, разных типов, с объяснением каждого неверного варианта.
5. **Бои:** финальное задание ветки (файловое, а после включения грейдера — с исполнением кода).
6. **Сцены сюжета** для веток (`docs/story/`).
7. **Тесты контента:**
   - покрытие индекса 100%;
   - банк не меньше 12 на навык;
   - опоры существуют и без циклов;
   - запрещённые слова и внешние ссылки;
   - решения боёв проходят свои проверки.
8. **PR → проверка владельцем → публикация** (владелец, `launch-course.mjs`).

**Оценка.** Агент делает персонажа среднего размера (около 150 навыков) за 2–4 дня работы. Сезон из 4–5 персонажей — 2–3 недели.

**Существующие курсы** (HTML, CSS, JS, SQL) переходят на новую модель так:
- у каждого навыка сейчас 2–3 квиза, банк надо добрать до 12 вопросов;
- опоры размечаются по навыкам;
- уроки остаются.

## 6. Монетизация: подписка с уровнями

Решение владельца от 2026-11-05: обучение продаётся **подпиской от $50 до $2 000 в месяц**. Чем дороже уровень, тем больше в нём живого времени людей: наставников, ревьюеров, команды. Платформа одна, уровни отличаются поддержкой и глубиной.

### Принципы

1. Платят за **доступ, проверку и людей**, никогда за скорость прокачки или силу персонажа.
2. Пролог (ПК, Браузер) и акт HTML бесплатны полностью: ученик должен влюбиться до оплаты.
3. Освоенное не отнимается. После окончания подписки прогресс, уровни и достижения остаются, закрываются только платные ветки и услуги.
4. Цена уровня оправдана тем, что в нём есть. Обещаний трудоустройства нет: это юридический и репутационный риск.

### Уровни

| Уровень | Цена в месяц | Что входит |
|---|---|---|
| **Бесплатный** | $0 | ПК, Браузер, HTML целиком; первые 2 ветки остальных персонажей; карта, задания дня, серии, достижения |
| **Искатель** | $50 | Все персонажи и ветки; бои с Багом с автопроверкой; ржавчина и повторение; сертификаты персонажей; новые персонажи сезона сразу |
| **Подмастерье** | $150 | Всё из «Искателя» + проверка боёв живым ревьюером (до 8 работ в месяц, ответ за 48 часов); групповой разбор раз в неделю; закрытый чат потока |
| **Инженер** | $400 | Всё из «Подмастерья» + личный наставник: созвон 1:1 раз в неделю (45 минут), личный план прокачки, ревью без лимита за 24 часа |
| **Архитектор** | $900 | Всё из «Инженера» + командный проект в группе по 3–5 человек с настоящим GitHub-репозиторием: ревью PR наставником, роли в команде; разбор портфолио |
| **Наставничество Pro** | $2 000 | Всё из «Архитектора» + наставник-сеньор: 1:1 дважды в неделю, ежедневная связь в рабочие дни, программа под цель ученика, моковые собеседования, разбор резюме и стратегия поиска работы; мест мало |

**Годовая оплата** — скидка 2 месяца (10 вместо 12). Первые 7 дней «Искателя» — бесплатно.

**Ограничение мест.** Уровни с людьми ($150 и выше) ограничены вместимостью наставников. Набор идёт по мере свободных мест, иначе — лист ожидания. Без этого качество упадёт.

### Что из этого уже есть в коде

| Нужно уровню | Есть | Не хватает |
|---|---|---|
| Доступ к веткам | Entitlement с `expires_at`, Offering с платным доступом | Подписочный источник Entitlement и доступ по веткам (ADR) |
| Проверка ревьюером | Submission → ValidationResult → Evidence (F4); роль `validation.record` | Очередь работ ревьюеру, срок ответа, интерфейс ревью |
| Групповые разборы, созвоны | CourseRun, Session, Attendance (F3) | Запись на созвон, ссылка на встречу, календарь |
| Командный проект | Group/Team, GitHub App, PR/review/check-факты (F6, в продакшене не активны) | Запуск обработчиков GitHub (ADR-0071), интерфейс команды |
| Личный план | Рекомендации и готовность (F8) | Интерфейс наставника |
| Подписка и продление | Разовая оплата Paddle, Purchase → Entitlement | Подписки: продление, отмена, неуспешное списание, отзыв доступа |

### Провайдер и валюта

- **Цены в долларах.** Это рынок русскоязычных учеников по всему миру. Paddle поддерживает подписки и доллары, уже интегрирован (ADR-0048). Он действует как продавец (Merchant of Record) и сам берёт на себя налоги в странах покупателей.
- **Ученики с картами российских банков.** Paddle, по имеющимся сведениям, их не принимает: владельцу нужно проверить. Для них нужен второй провайдер — ЮKassa или CloudPayments, цены в рублях, чеки по 54-ФЗ. Отдельный ADR.

### Блокеры до приёма денег

Это обязательно, а не пожелания.

1. **Подписки в коде:**
   - ADR;
   - события Paddle о продлении, отмене и неуспешном списании;
   - Entitlement продлевается или закрывается;
   - льготный период при неуспешном списании.
2. **Оферта с условиями подписки, политика конфиденциальности, согласие на обработку ПД.** Черновик — #174. Условия отмены и возврата должны быть понятны до оплаты.
3. **152-ФЗ** для учеников из России. Решение в #174.
4. **Возвраты:** за неиспользованный период и при отказе в первые дни.
5. **Люди для уровней $150+:** наставники, ревьюеры, их загрузка. Без них продавать эти уровни нельзя.

## 7. Программа испытателей («Отряд испытателей»)

**Цель:** живые люди проходят игру до запуска оплаты и приносят отчёты о недочётах и предложения. Взамен они получают полный доступ бесплатно на время.

### Поток

1. **Заявка.** Страница `/testers` → форма:
   - уровень подготовки;
   - сколько часов в неделю готов уделять;
   - устройство и браузер;
   - как связаться (email аккаунта);
   - согласие с правилами испытателя и с обработкой данных.
   Нужен вход в аккаунт.
2. **Отбор.**
   - Владелец видит заявки в Studio («Испытатели») и принимает или отклоняет.
   - Набор идёт волнами, у волны есть лимит мест (например, 30).
   - Можно включить автоприём, пока есть места.
3. **Доступ.**
   - Принятый получает Entitlement «Пропуск испытателя» на 4 недели: всё, что даёт уровень «Искатель» ($50). Уровни с людьми испытателям не входят.
   - Источник Entitlement — `tester_grant`, а не Purchase.
4. **Норма** на каждую неделю (настраивается на волну):
   - не меньше 3 активных дней (засчитанное задание в день);
   - не меньше 5 навыков с новым Evidence;
   - не меньше 2 отчётов (недочёт или предложение), хотя бы 1 из них не отклонён как пустой.
5. **Контроль.**
   - Норма вычисляется из истории событий и отчётов, без отдельного планировщика: статус считается при каждом входе.
   - Испытатель видит прогресс нормы на своей странице и в шапке.
   - Неделя без нормы — предупреждение. Две подряд — пропуск испытателя закрывается, остаётся бесплатный уровень, прогресс сохраняется.
   - Выполнил норму все 4 недели — продление на следующую волну и значок «Ветеран отряда».
6. **Отчёты.**
   - Кнопка «Сообщить» на каждой странице урока, карты и персонажа.
   - Поля: тип (ошибка / непонятно / предложение), текст, автоматически страница, урок, версия сайта и браузер. Скриншот — позже.
   - Ограничение частоты как у остальных записей (ADR-0070).
   - Владелец в Studio ведёт отчёты по статусам: новый → принят / дубль / отклонён → исправлен.
   - Испытатель видит статусы своих отчётов. Каждый принятый отчёт — «трофей» в коллекции Охотника на Багов: это связь с сюжетом.

### Модель (Delivery и новые модули)

- **`tester_programs` / `tester_waves`** — волна: даты, лимит мест, норма.
- **`tester_applications`** — заявка: статус `pending` → `accepted` / `rejected` / `withdrawn`.
- **`feedback_reports`** — отчёт, его статус и связь со страницей. Отчёты может присылать любой ученик; для испытателя они входят в норму.
- **Entitlement с источником `tester_grant`.** Commerce сейчас создаёт Entitlement только через Purchase. Нужен ADR: допустимые источники Entitlement (`purchase` | `tester_grant` | `operator_grant`), атомарность с событием outbox.

Все таблицы — с RLS по организации. Каждая смена статуса пишется вместе с событием outbox в одной транзакции.
