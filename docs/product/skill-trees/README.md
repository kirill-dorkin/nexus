# Деревья навыков персонажей

Версия 1, 2026-11-05. Задача владельца: каждый персонаж — технология, и **все её возможности можно изучить буквально**. В этой папке на каждого персонажа описано полное дерево навыков: ветки, навыки, опоры, бои и способности. Здесь же — общие правила прокачки.

Документы описывают **цель**. Карта, которую видит ученик, строится из опубликованных курсов. Персонаж выходит в продакшен, когда его курс покрывает дерево целиком (тест покрытия, раздел 2.3).

## 2. Как строится дерево

### 2.1 Источник полноты

У каждого персонажа есть **источник истины о возможностях** — официальная спецификация или справочник нужной версии. Он указан в начале файла персонажа, например:

| Персонаж | Источник |
|---|---|
| HTML | HTML Living Standard |
| CSS | спецификации CSS WG |
| JavaScript | ECMA-262 |
| React | справочник react.dev |
| PostgreSQL | документация PostgreSQL 18 |

Из источника строится **индекс покрытия** `coverage-index.json` — список всех возможностей:
- все элементы и атрибуты;
- все свойства;
- все API, хуки, директивы;
- все команды и флаги;
- все конструкции языка.

Индекс составляется по оглавлению справочника; уроки пишутся своими словами, без копирования и без внешних ссылок.

### 2.2 Размер навыка

Навык — то, что ученик может доказать одним тестом из 5 вопросов.
- **Не мельче:** не «атрибут `alt`» отдельно от «картинки», а «изображения: `img`, `alt`, размеры, загрузка».
- **Не крупнее:** не «формы целиком», а «типы полей», «проверка форм», «отправка».
- **Группировка:** однородные возможности (например, 20 свойств типографики) — один навык, если их можно спросить вместе. Каждая запись индекса всё равно привязана к навыку.
- **Объём:** у персонажа обычно 40–110 навыков, у маленьких технологий (Astro, Prisma, Vitest) — 15–25. Навык крупный: за ним стоит группа записей индекса.

### 2.3 Уровни глубины веток

Каждая ветка относится к одному уровню глубины. От уровня зависит вес навыка в уровне персонажа (раздел 3.2).

| Уровень | Что это | Вес |
|---|---|---|
| **Основа** | Без этого технологией нельзя пользоваться | 3 |
| **Практика** | Повседневная работа | 2 |
| **Продвинутое** | Сложные случаи, производительность, архитектура | 1,5 |
| **Полное покрытие** | Редкие возможности, весь справочник | 1 |
| **Изнутри** | Как это устроено: внутренности, спецификация | 1 |

**Тест покрытия персонажа:**
- каждая запись индекса привязана к навыку;
- у каждого навыка есть урок, банк из 12+ вопросов и опоры;
- у каждой ветки уровня «Практика» и выше есть бой.

### 2.4 Опоры

- Внутри персонажа навык по умолчанию опирается на предыдущий навык ветки. Ветка опирается на ветки, перечисленные в её строке «Опоры».
- Между персонажами — явные связи, например `react-effects` ← `js-closures`, `js-promises`.
- Граф без циклов, это проверяется сборкой карты.

### 2.5 Бои

Финал ветки уровня «Практика» и выше — практическое задание с серверной проверкой.

| Технологии | Проверка |
|---|---|
| HTML, CSS | статическая (ADR-0073) |
| SQL | SQL-песочница |
| JS, TS, фреймворки, сервер, тесты, инфраструктура | грейдер |

До включения грейдера бои этих персонажей заменяются тестом ветки.

## 3. Как прокачивается персонаж

### 3.1 Цикл навыка

Без изменений, по `skill-freshness@1` (ADR-0076):
1. Изучить урок.
2. Подтвердить тестом: 5 вопросов, 4 для зачёта (ADR-0075).
3. Повторять в срок: 3 дня → 7 → 21 → 60 → 180 → 365.
4. Через 7 дней после срока навык тускнеет, затем забывается.
5. Вспомнить забытый навык — подтвердить заново; срок становится на ступень короче.

### 3.2 Уровень персонажа — взвешенный (`level@2`)

Уровень = ⌊ Σ вес активных навыков ÷ Σ вес всех навыков × 100 ⌋.

Сейчас (`level@1`) все навыки равны. Тогда основы дают столько же, сколько редкая возможность из справочника, и уровень растёт медленно там, где учиться важнее всего. С весами ученик, освоивший основу и практику, — уже Практик, а Легенда — это всё, включая справочник. Нужна поправка ADR-0074.

### 3.3 Ранги

| Ранг | Уровень | Что это значит |
|---|---|---|
| Новичок | 0 | Начал |
| Ученик | 20 | Основа почти освоена |
| Практик | 40 | Основа и практика: можно работать джуном |
| Мастер | 60 | Плюс продвинутое |
| Эксперт | 80 | Почти весь справочник |
| Легенда | 95 | Всё, включая «изнутри» |

### 3.4 Способности

У персонажа 5–8 **способностей** — вехи, показанные значками на портрете. Способность активна, пока активны все её навыки, и гаснет, если какой-то навык забыт. Например, у React: «Компоненты», «Состояние», «Эффекты», «Контекст», «Производительность», «Серверные компоненты», «Формы и действия».

### 3.5 Эволюции и союзники

- **Эволюция** — следующий персонаж линии: JavaScript → TypeScript, React → Next.js, Vue → Nuxt, Svelte → SvelteKit, Node.js → NestJS, Docker → Kubernetes. Открывается, когда базовый персонаж достиг ранга **Практик**.
- **Союзники** — персонажи, на навыки которых опираются ветки, например CSS → Tailwind. Подсказка «сначала прокачай союзника» показывается на закрытых навыках.

### 3.6 Обновление персонажа

Выход новой версии технологии добавляет ветку «Новое в версии N». Уровень пересчитывается: новые навыки ещё не подтверждены. Устаревшие возможности переезжают в ветку «Наследие» уровня «Полное покрытие»: их нужно уметь читать, а не писать.

## 4. Формат файла персонажа

```
# <Имя> — <класс>
Источник полноты · Версия · Опоры на персонажей · Эволюция · Способности
## Ветка (уровень) — опоры
- `key` — Название: что входит (ссылки на индекс)
Бой: ...
```

Ключи навыков стабильны: `<персонаж>-<тема>`. Существующие ключи HTML, CSS, JS и SQL сохраняются. Новые навыки получают новые ключи, а переименование ломает историю учеников.
