# Техническое задание: следующий этап развития Nexus

Версия 2, 2026-11-04. Основа — анализ `main` 199f95f.

Документ рассчитан на автономную работу: агент может весь день идти по пакетам работ из раздела 6 без вопросов владельцу. Остановиться и спросить он должен только там, где это прямо сказано. Порядок источников истины задан в `AGENTS.md`: код, миграции и тесты важнее этого документа, принятые ADR тоже важнее; этот документ — планирующий.

## 1. Итог анализа

**Архитектура построена корректно.**
- Модули общаются через публичные application-интерфейсы.
- Все таблицы с данными организаций защищены RLS (проверены все 64).
- Бизнес-состояние и событие outbox пишутся одной транзакцией.
- Доменные понятия разделены так, как описано в ADR.
- Тесты: 321 интеграционный тест бэкенда на PostgreSQL, около 3 200 юнит- и компонентных тестов, 31 e2e-сценарий с axe и бюджетами производительности.

**Продукт использует меньшую часть того, что построено.**
- В продакшене работает только бесплатное обучение: каталог, уроки, практика в браузере, квизы, «Моё обучение» и Studio.
- Из 108 маршрутов API сайт вызывает около 60.
- Без интерфейса или не запущены: навыки ученика, Guided Build, когорты, рекомендации, история событий, GitHub-проекты, грейдер и оплата.

**Есть проблемы надёжности и безопасности, важнее новых функций.**
- **Авария 2026-11-04.** Обновление NestJS 12 (#164) уронило API продакшена примерно на 50 минут, откат в #166. Локальные проверки прошли. Проверка продакшена отчиталась об успехе, потому что проверила предыдущую версию; исправление — #167.
- **Вход не защищён от перебора.** Ограничений частоты запросов нет ни на входе, ни на регистрации, хотя их требует `docs/security/baseline.md`.
- **Нет восстановления пароля и отправки писем.** Ученик, забывший пароль, теряет доступ, если не входил через Google или GitHub.
- **Нет политики конфиденциальности и согласия на обработку персональных данных.** Сайт собирает email, а по 152-ФЗ это обязательно.
- **У Web нет заголовков безопасности.** CSP, frame-ancestors, Referrer-Policy и Permissions-Policy не заданы; есть только HSTS от Vercel.
- **Ученик не может завершить курс.** Переход записи в `completed` разрешён только оператору (`progression.complete`).

## 5. Правила автономной работы

Эти правила дополняют `AGENTS.md` и `development-workflow.md` и не заменяют их.

**Можно без вопросов:**
- ветки, PR и слияние своих зелёных PR (squash);
- код, тесты, документы и ADR по пакетам из раздела 6;
- откат собственного PR, сломавшего продакшен.

**Обязательно для каждого PR:**
1. Перед пушем — `pnpm check` локально, в фоне.
2. Для изменений API или Web — ещё полный e2e: `E2E_BROWSER_CHANNEL=chrome pnpm test:e2e`. Для интеграционных тестов API (`pnpm test:integration`) нужны переменные `DATABASE_URL`, `DATABASE_MIGRATION_URL` и `DATABASE_WORKER_URL`: значения взять из `.env.example`. Локально падает только тест Neon-бутстрапа (нужен пароль суперпользователя из CI), это нормально.
3. Дождаться зелёного CI `verify`.
4. **После слияния** дождаться, пока `https://nexus-lake-nine-17.vercel.app/v1/health` вернёт `release` нового коммита, и проверить `/v1/public/learning` и `/`. Если продакшен сломан — немедленно откатить своим PR.

**Нельзя сливать без владельца** (подготовить PR и остановиться):
- PR, которому нужна **новая миграция в продакшене**. Деплой не применяет миграции, их применяет владелец. Порядок такой: PR только с миграцией (аддитивной, совместимой со старым кодом) → владелец применяет → PR с кодом.
- Крупные версии зависимостей среды выполнения API (NestJS, Fastify, pg, zod, pino).
- Юридические тексты, всё, что связано с почтой, оплатой и выполнением кода ученика вне браузера.
- Публикацию курсов: её запускает владелец одной командой.

**Остановиться и сообщить:**
- если CI падает трижды по одной причине;
- если для продолжения нужны секрет, доступ к Vercel или продакшен-база;
- если найдена уязвимость, которую нельзя закрыть в рамках пакета.

**Отчёт в конце дня** (в ответе и в описании последнего PR): что слито (ссылки), что ждёт владельца и какой командой, что не сделано и почему.

## 6. Пакеты работ

Пакеты выполняются по порядку; внутри пакета — по шагам. Размеры: S — до дня, M — 2–5 дней, L — больше.

### WP-1. Надёжность и защита продакшена — M

**WP-1.1. Слить #167** (проверка продакшена ждёт деплоя своего коммита). Приёмка: после слияния проверка на пуше в `main` дожидается своего `release` и проходит.

**WP-1.2. Заголовки безопасности Web (A9)** — `apps/web/next.config.ts`, `headers()`:
- `Content-Security-Policy`:
  - `default-src 'self'`;
  - `script-src 'self'` плюс то, что требует Next. Если инлайн-скрипт темы требует `'unsafe-inline'`, перевести его на хеш;
  - `'wasm-unsafe-eval'` для PGlite;
  - `frame-src`: YouTube (`https://www.youtube-nocookie.com`, `https://www.youtube.com`), `blob:` и `data:` для фреймов практики (проверить, как практика задаёт фреймы: `srcdoc` наследует CSP родителя);
  - `worker-src 'self' blob:`;
  - `connect-src 'self'`;
  - `img-src 'self' data: https://i.ytimg.com`;
  - `frame-ancestors 'none'`.
- `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, `Permissions-Policy` с запретом камеры, микрофона и геолокации.
- Сначала выпустить как `Content-Security-Policy-Report-Only` и прогнать e2e. Нарушения ловить в e2e через `page.on('console')`. Только потом перевести в действующий режим.

Приёмка: e2e 31/31 без нарушений CSP в консоли, в том числе на SQL-уроке и на практике JS (песочница-фрейм со своими скриптами); новый e2e-тест проверяет наличие заголовков.

**WP-1.3. Ограничение частоты запросов (A8).** На Vercel много инстансов, поэтому счётчики в памяти не работают — нужно хранить их в PostgreSQL.
- Миграция (отдельный PR, см. §5): таблица `platform_internal.rate_limit_buckets`, поля `key_hash bytea`, `window_start timestamptz`, `count int`, PK (`key_hash`, `window_start`). Доступ только через функцию `SECURITY DEFINER`, которая атомарно увеличивает счётчик и возвращает его значение. Очистка — удаление окон старше суток каждым сотым вызовом.
- Ключ — HMAC-SHA256 от (маршрут, IP клиента из заголовков Vercel, для входа ещё нормализованный email) с секретом `RATE_LIMIT_KEY`. Сырые IP и email не хранятся.
- Лимиты:

  | Маршрут | Ключ | Лимит |
  |---|---|---|
  | `POST /auth/login` | IP | 20 / 10 мин |
  | `POST /auth/login` | email | 10 / 10 мин |
  | `POST /auth/register` | IP | 5 / час |
  | `POST /me/learning/.../quiz/.../check` | IP | 120 / 10 мин |
  | `POST /telemetry/web` | IP | 60 / мин |

- Ответ при превышении: 429 с `Retry-After`. Операционное событие `auth.rate_limited` без идентификаторов (ADR-0052). Если база или секрет недоступны — пропускать запрос, а не блокировать вход, и писать операционное событие.
- ADR-0070 «Rate limiting» фиксирует модель угроз, ключи, хранение и отказоустойчивость.

Приёмка: интеграционные тесты — 21-я попытка входа с одного IP получает 429, другой IP проходит, ключи в таблице не раскрывают IP/email; e2e не задевают лимиты. **Код сливается только после того, как владелец применил миграцию и задал секрет.**

### WP-5. Задания «скачай → сдай → получи разбор» — L

**Решения этой версии** (их можно изменить позже, ADR-0073):
- Новый тип активности `assignment.files`. Доверенная серверная проверка (ValidationResult → Evidence) — только для HTML и CSS. Задания с JS или SQL в этой версии проверяются только в браузере и Evidence не создают, по ADR-0064.
- Сдача — текстовые файлы в `Submission.payload` (`{ files: { path: content } }`). Хранилище файлов не нужно.

**Манифест** — `packages/contracts/src/course-manifest.ts`:

```json
{
  "type": "assignment.files",
  "slug": "first-page",
  "title": "Первая страница",
  "instructions": "…",
  "skillKeys": ["html-structure"],
  "lang": "html",
  "starterFiles": { "index.html": "<!doctype html>…", "style.css": "" },
  "allowedFiles": ["index.html", "style.css"],
  "checks": [{ "label": "Есть заголовок первого уровня", "selector": "h1" }],
  "solutionFiles": { "index.html": "…" }
}
```

- `checks` и `solutionFiles` — защищённый контент, ученику не отдаются. Хранятся в новой таблице `learning_content.assignment_check_configs` по образцу `quiz_validation_configs` (миграция 000040), с RLS и триггерами черновика. **Миграция — отдельный PR, ждёт владельца.**
- Публикация отклоняет задание, если `solutionFiles` не проходит собственные `checks` (серверная проверка через WP-4).

**Валидатор** — `learning-validation/domain/validator-registry.ts`: `assignment.files@1` — детерминированная статическая проверка через `@platform/checks`. Результат — список `{ label, passed, hint? }` и `score` (доля пройденных); `passed`, если пройдены все проверки. Сбой инфраструктуры — `system_error`.

**API.** `POST /v1/me/learning/:org/:offering/assignments/:activitySlug/submissions` по образцу `checkQuiz` в `learner-learning.service.ts`:
- `attemptKey`;
- тело `{ files }`; лимиты: до 50 файлов, до 200 КБ на файл, до 1 МБ всего, пути из `allowedFiles`, без `..` и абсолютных путей;
- фазы — новая попытка → Submission → проверка → ValidationResult → нормализация в Evidence;
- ответ — `{ attemptNumber, outcome, score, checks: [{ label, passed, hint }] }`, без эталонов;
- лимит частоты из WP-1.3: 30 сдач / 10 мин на IP.

**Web** — урок, блок `activity` с `kind: "homework"`, новый компонент `AssignmentBlock`:
- «Скачать задание»: zip собирается в браузере из `starterFiles` и `README.md` с условием (библиотека `fflate`, загрузка по требованию).
- «Сдать решение»: принимает zip или отдельные файлы (`<input type="file" multiple>` и перетаскивание). Распаковка с проверкой заявленного и фактического размера (защита от zip-бомб); лишние и бинарные файлы отбрасываются, ученик видит предупреждение.
- Сразу после выбора файлов — предварительный разбор в браузере (`@platform/checks`) с пометкой «предварительно». Кнопка «Отправить на проверку» отправляет файлы на сервер, и показывается отчёт сервера.
- Отчёт: список с ✓ и ✗, подсказки, номер попытки, `aria-live` для результата.
- Анонимному ученику — предложение войти, как у квиза.

**Studio.** JSON-редактор принимает `assignment.files`. В ручной редактор — минимальная форма: условие, файлы-заготовки (textarea на файл), проверки в JSON. Предпросмотр сдаёт `solutionFiles` и показывает отчёт.

**Тесты:**
- контракт манифеста (валидные и невалидные задания);
- интеграционные: успешная и неуспешная сдача, лимиты, `..` в путях, чужая организация, повторная сдача, отсутствие эталонов в ответе, ключ попытки, `system_error`;
- компонентные: загрузка, отбрасывание файлов, отчёт;
- e2e: скачать → сдать эталон → «засчитано», сдать с ошибкой → видны пункты → исправить → «засчитано», навык меняется (WP-3); axe на блоке задания; бюджет урока с заданием не больше +30 КБ.

**Порядок PR:**
1. Контракт манифеста и валидатор, без маршрута.
2. Миграция (ждёт владельца).
3. API и публикация.
4. Web.
5. Studio.
6. Пример задания в `docs/examples` и в фикстуре e2e.

### WP-6. Меньше JavaScript — S–M

- Клиентские компоненты разбирают ответы API через `zod/mini` или узкие клиентские схемы в `@platform/contracts`; серверный код продолжает использовать полные схемы.
- Приёмка: бюджеты в `tests/e2e/budgets.ts` снижены до факт + 15 %, тесты контрактов зелёные, поведение не меняется.

### WP-7. Подготовка решений владельца — S, без слияния кода

Подготовить черновики ADR и PR, **не сливать**:
- **ADR «Завершение курса учеником»:** когда разрешить переход в `completed` для своей бесплатной записи (все обязательные активности пройдены, политика готовности, если задана), что меняется в интерфейсе и событиях. По текущим правилам производный процент не завершает запись, поэтому нужна явная команда ученика.
- **ADR «Учебная воронка»:** обезличенные дневные агрегаты по шагам урока; источники — канонические события (Submission, Evidence, Enrollment) и клиентские события анонимов по контракту ADR-0067; хранение, срок, экран в Studio.
- **Правовой минимум:** страницы `/privacy` и `/terms`, ссылка в подвале, флажок согласия на регистрации с записью версии согласия. Тексты и реквизиты оператора — от владельца; в PR — каркас без текстов.
- **Письма и восстановление пароля:** варианты провайдера, модель угроз сброса (одноразовый токен с хешем в БД, 30 минут, лимит частоты), объём работ.

### WP-8. Задания в курсах — M (контент, после WP-5)

- По 1–2 задания `assignment.files` в конце каждой главы HTML и CSS по правилам контента (без сюжета, без внешних ссылок, полное покрытие темы). Тесты `*-track-manifest.test.ts` проверяют, что эталоны проходят проверки.
- Публикация — командой владельца (§8).

## 7. Нефункциональные требования

- **Безопасность.**
  - Код ученика не выполняется в Web, API или Worker. Статический разбор HTML/CSS выполнением не считается, но идёт с лимитами размера и времени.
  - Новые таблицы — с RLS; эталоны — защищённый контент.
  - Все загрузки ограничены по размеру, числу и путям.
- **Доступность.** WCAG 2.2 AA; новые страницы и блоки — в `accessibility.spec.ts`; результат проверки озвучивается (`aria-live`).
- **Производительность.** Бюджеты не повышаются без объяснения в PR; тяжёлые модули грузятся по требованию.
- **Наблюдаемость.** Операционные события по ADR-0052, без персональных данных; ошибки клиента — по ADR-0067.
- **Совместимость.** Миграции аддитивные и не ломают текущий код; удаление колонок — только отдельным PR с владельцем.
- **Качество.** `pnpm check`, интеграционные тесты и e2e — до пуша; CI — до слияния; продакшен — после.
